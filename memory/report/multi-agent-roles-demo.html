多角色 Agent 协作架构

像对冲基金的交易团队一样，不同角色各司其职，协作完成复杂任务。

类比：对冲基金的团队分工

真实对冲基金的角色
Portfolio Manager — 最终决策者，综合所有意见
Quant Researcher — 开发因子、策略、模型
Market Analyst — 技术面和基本面分析
Risk Manager — 监控风险敞口，设定限制
Execution Trader — 负责实际下单执行
Compliance — 合规审查
Claw Agent 的角色映射
Coordinator — 综合协调者（最终给用户的建议由它产出）
Quant — 因子研究、策略回测
Analyst — 技术分析、消息面分析
Risk — 风险评估、仓位建议
Sentinel — 市场监控、预警、信号跟踪
用户 — Portfolio Manager（最终拍板）
注意最后一行：用户 = Portfolio Manager。
在真实基金里，PM 听取所有人的意见但自己做最终决策。在 Claw 里，用户就是 PM。
Coordinator 的角色不是"替用户决策"，而是"把团队的分析结果整合成一份清晰的报告给 PM 看"。

多角色在 Harness 架构里的位置

Planner 在哪？和角色们是什么关系？
Planner 不是团队里的一个角色，它是 P-G-E 循环的第一步——在角色们开始工作之前，决定需要谁、做什么、怎么配合。
用户: "分析 BTC 并给我操作建议" │ ├─ 🧠 Planner ← P-G-E 的 P — 调度者，不是团队成员 │ ├─ 意图分析: "综合市场分析 + 操作建议" │ ├─ 角色选择: Analyst + Risk（不需要 Quant） │ ├─ 任务分配: Analyst→技术面+消息面, Risk→仓位+风控 │ └─ 输出: ExecutionPlan { agents, focus, parallel, ... } │ ├─ Generator ← P-G-E 的 G — 多角色协作在这里发生 │ ├─ fork → Analyst（按 Planner 分配的 focus 执行） │ │ └─ 技术分析 + 消息面 → 研究报告 │ │ │ ├─ fork → Risk（按 Planner 分配的 focus 执行） │ │ └─ 风险评估 + 仓位建议 → 风险报告 │ │ │ └─ 🎯 Coordinator（读取所有报告，综合输出） │ └─ 消除矛盾 → 整合为统一建议 │ ├─ Evaluator ← P-G-E 的 E — 独立校验 │ └─ → 用户 👤（PM 最终拍板） 五个角色的定位: Planner = 项目经理（不干活，只分任务、选人） Analyst = 分析师（干活） Quant = 研究员（干活） Risk = 风控官（干活） Sentinel = 哨兵（独立后台运行，异常时唤起 Planner） Coordinator = 报告撰写人（综合大家的成果） Evaluator = 质检员（独立检查最终报告） 用户 = 老板（最终拍板）
Planner 的三种触发方式：

1. 用户发起 — 用户在对话框输入问题 → Planner 分析意图、选择角色、分配任务
2. Sentinel 唤起 — Sentinel 检测到异常 → 唤起 Planner 进入紧急模式 → Planner 快速调度角色
3. 学习循环触发 — 周期性复盘/因子衰减检测 → Planner 决定是否需要研究团队介入

Planner 做的事情：分析意图 → 选角色 → 分任务 → 定并发/串行 → 设超时 → 定是否需要 Evaluator
Planner 不做的事情：不调工具、不搜索、不分析数据 —— 它只管"派谁去做什么"
什么时候用单角色，什么时候用多角色
用户请求 模式 参与角色
"BTC 现在多少钱？" 单角色 Analyst
"什么是 RSI？" 单角色 直接回复（无需角色）
"分析 BTC 走势给我建议" 多角色 Analyst + Risk + Coordinator
"设计一个新因子并回测" 多角色 Quant + Risk + Coordinator
"帮我构建一个完整的 BTC 交易策略" 全员协作 Analyst + Quant + Risk + Sentinel + Coordinator
