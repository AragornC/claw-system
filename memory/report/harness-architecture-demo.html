工具注册表与权限模型
工具是受管执行接口。能力越强，约束越细。权限分三级：auto（自动执行）、ask（需确认）、deny（禁止）。
工具来源分层
工具可以从多种来源注册，统一接入 Tool Orchestration 层。
内置工具（Built-in）
由系统代码定义，如 web_search、code_exec。在 Rust 后端或前端直接实现。
Skill 工具
由 Skill 文件定义的领域工具包。如 "因子分析 Skill" 内含 calculate_factor、get_klines 等工具组合。
MCP 工具
外部 MCP Server 暴露的工具。通过标准协议发现和调用，如接入财经数据供应商的 MCP。
用户自定义工具
用户通过配置注册的自定义 HTTP 回调或脚本。需要更严格的权限审查。
可靠性设计 — 错误即主路径
交易场景中，错误不是异常——它是最常走的路径。系统必须在每个层级都有对应的恢复机制。
按层级的容灾机制
L1 控制平面
Prompt 校验 · 指令优先级冲突检测 · 规则违反时 fallback 到安全默认值
L2 Query Loop
上下文超限 → auto compact · 流中断 → synthetic 收尾 · API 错误 → 重试/切模型 · 死循环检测
L3 P-G-E
Evaluator 打回 → 重新 Plan · 连续失败熔断 · 计划步骤超时 · 子 Agent 隔离失败
L4 Tool
工具超时 → synthetic error · 权限拒绝 → 降级路径 · 并发冲突 → 顺序回退 · API key 失效 → 提示配置
L5 State
Compact 失败 → truncate head · 记忆污染 → 验证后再信任 · Session 丢失 → persist 恢复
交易专属
下单前二次确认 · 仓位上限锁定 · 回撤触发 Kill Switch · 网络断开冻结挂单 · 订单状态轮询兜底
恢复原则
恢复的目标是继续工作，不是回忆历史。
Compact 后保留的是"接下来该做什么"，而非"之前聊了什么"。交易场景中，恢复后必须先校验当前持仓和挂单状态，再继续执行策略。
Harness 十原则 → Claw 落地映射
逐条对应 Claude Code Harness Engineering 的设计原则，映射到 Claw 交易 Agent 的具体设计决策。
# 原则 Claw 落地
1 模型是不稳定部件 不信任模型的交易决策 → 所有下单必经 Evaluator 独立校验 + 用户确认。模型是"建议者"不是"执行者"。
2 Prompt 是控制平面 System Prompt 分层：全局规则 → 交易约束（仓位限制、风控参数）→ Skill 规则 → 用户自定义。优先级链保证风控规则不被覆盖。
3 Query Loop 是心跳 有状态执行循环：跨轮维护当前策略状态、持仓快照、待确认操作。每轮开始先治理上下文，再推理。
4 工具是受管执行接口 web_search=auto，calculate_factor=auto，place_order=ask（必须确认），cancel_all=deny（需手动执行）。能力越强约束越细。
5 上下文是工作内存 Compact 保留：当前策略参数 + 最近信号 + 持仓状态。丢弃：历史闲聊、已完成的分析过程。Session Memory 只为继续工作。
6 错误路径是主路径 交易所 API 超时、K线数据缺失、模型幻觉因子名 — 全部有 synthetic error 和降级路径。autocompact 连续失败 3 次触发熔断。
7 恢复目标是继续工作 崩溃恢复后：先查交易所真实仓位 → 对比本地状态 → 修正后继续。不从头回溯对话，直接从当前状态续行。
8 多代理 = 不确定性分区 子 Agent 隔离：因子研究 Agent、策略回测 Agent、信号执行 Agent 各自独立上下文。协调者综合结果，不外包理解。
9 验证必须独立 Evaluator 是独立的 LLM 调用（甚至可以是不同模型），不复用 Generator 的上下文。交易信号必须经独立验证才能进入执行队列。
10 团队制度重于个人技巧 交易规则写入 claw.rules（类似 CLAUDE.md）：最大仓位比例、允许的交易对、回测要求等。Skill 文件标准化，Hook 锚点（PreTrade / PostTrade）。
