方案 A — Unified Diff
最经典，删除行红色 − 添加行绿色，行号左右各一列。字符级高亮标出精确改动点。最紧凑，适合改动少的修复。
方案 B — Split Diff
左旧右新，对比最直观，像 GitHub 的 side-by-side。改动多时更容易看懂前后差别，但占宽度较大。
方案 C — 摘要 + 折叠 Diff
先展示"修复了什么"的人话摘要，diff 默认折叠，点击才展开。适合大多数用户不需要看 diff 的场景。
