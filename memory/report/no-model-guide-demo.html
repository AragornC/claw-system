Demo

用户首次启动、或所有模型均断开连接时，对话框应如何引导用户去连接模型。以下提供三种方案对比，可切换「未连接」状态查看效果。

模拟状态： 已连接模型 (gpt-5.4)

方案 A — 底部 Banner

推荐

在输入框上方展示一条提示 banner，引导用户前往设置

行为说明
已连接模型时（正常态）
·Banner 不显示，输入框和发送按钮正常可用
·模型选择器显示当前模型名，点击展示可用模型列表
未连接任何模型时
A 输入框上方出现金色 Banner，写明原因 + 「去设置」直达按钮
A 输入框 placeholder 变为「请先连接模型」，发送按钮禁用
C 模型选择器变为红色警告「⚠ 未连接模型」
C 点击选择器展开下拉，可直接选择提供商跳转配置页
实现判断（AgentPanel.tsx）
// 所有 provider 均未连接
const noModel = PROVIDER_IDS
  .every(pid => !auth[pid]?.connected);
试试看：先把上方开关切到「未连接」，再点左侧面板的「⚠ 未连接模型」，查看 C 的下拉效果

推荐实施策略

建议采用 方案 A + C 组合： 正常情况下模型选择器显示当前模型（方案 C 的下拉逻辑保持）； 当检测到 noConnectedModel 状态时，在输入框上方插入 banner（方案 A）， 同时模型选择器换成警告色并点击后展示方案 C 的引导下拉。 输入框和发送按钮在未连接时禁用，placeholder 改为「请先连接模型」。 实现方式：在 AgentPanel.tsx 中判断 PROVIDER_IDS.every(pid => !auth[pid]?.connected) 即可。
